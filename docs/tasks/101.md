# #101 — Recover the `||` knowledge the three-point domain throws away

`Reached::Sometimes` holds 17,892 file uses and treats them all as unknowable, but some are knowable.

`a || b` runs `b` only if `a` failed. So a call that exited NON-ZERO on such a chain proves `b` ran: if `a` had succeeded the chain would have exited 0. That is the exact mirror of the `&&` rule already implemented (exit 0 on an `&&` chain proves every link ran), and it is deliberately absent — `Reached::Sometimes` was made a single catch-all bucket so `a && b || c` had somewhere to go without the domain guessing.

To do it properly the domain needs a fourth point, `OnFailure`, plus `Reached::and` extended: OnSuccess ∧ OnFailure is genuinely unknowable and must still collapse to a catch-all, so `Sometimes` stays.

MEASURE FIRST. 17,892 is the whole Sometimes bucket, and most of it is `&&` demoted by `forget_discarded_status` (an `&&` in a segment whose status a later `;` discarded), NOT `||` at all. The recoverable slice is only the `||` right-hand sides in the FINAL segment of a call that failed. Could be a few hundred. Not worth a fourth domain point if so — measure before building.

Same caveat as everywhere else here: the aggregate hides compensating errors. Check a hand-written three-line script through the reader and read every answer, not just the corpus total (that is how both bugs in 16319f4 were found).

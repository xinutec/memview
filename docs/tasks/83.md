# #83 — Reach a place in a long transcript by landmark, not by paging

A 241 MB transcript can be paged back to any point — the cursor is a byte offset and nothing caps it — but only 400 events at a time from wherever you are, so anything an hour old is unreachable in practice. Measured: the picture sent at 18:42Z sits at line 94,282 of 105,370, about 24 MB behind the end.

⚠ A byte offset is the right cursor and a useless measure. One picture is 50 kB of base64 on a single line, a tool result can be half a megabyte, a sentence is 90 bytes — so there is no relation between file position and reading position, and a scrollbar over the file or a "40% through" would both be lies. That rules out virtual-scrolling the whole file, which is otherwise the obvious answer.

The design: the reader gets "go to" rather than "earlier" — their own messages by day, plus pictures sent and compaction boundaries. Those are the only landmarks anybody remembers. Not assistant text, not tool calls: they are the bulk and never the target.

MEASURED 2026-08-05, and it cuts most of the intended complexity:

- Substring scan of a whole transcript runs at ~2.5 GB/s on this machine (0.4 ms/MB): 241 MB in 55 ms, 313 MB in 127 ms, and the largest file on the disk — the health session's 2.7 GB — in 1.08 s. Read with ugrep, which is SIMD-tuned; a memchr-based Rust scan should be in the same class but that is NOT yet measured, and it is the one number to take before building anything.
- Landmarks are a rounding error of the file. Of 105,370 lines: 46,994 assistant, 29,562 user-type — but only 1,943 of those are not tool results (3 MB, 1.2% of the file), and 1,624 survive the plumbing filter. Perhaps 1,500 are genuine landmarks once task notifications and compaction preambles go. An index would be ~150 kB against 241 MB, 0.06%.

So: NO INDEX SIDECAR to begin with. Walk on demand when the reader opens "go to" — 130 ms for an ordinary large transcript is under a tap's worth of latency, off the executor like Roster::tasks. The sidecar with a mark-and-extend only earns its complexity for the multi-gigabyte outliers, and it can be added behind the same endpoint without the client knowing.

First step is therefore the endpoint and the jump strip, not the cache.

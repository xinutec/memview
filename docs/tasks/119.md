# #119 — Resuming a session silently drops it back to Manual

**Found while restarting a stalled session 2026-08-08.** The `hardware` session was running in `auto`. After `POST /api/sessions/{id}/stop` and `POST /api/sessions {resume: id}`, its summary came back `"mode":"default"` — Manual.

The id is kept, the transcript is kept, the conversation is kept. The permission mode is not, and nothing says so: the console shows the new mode as though it had always been that, and the only way to notice is to have read the old summary first.

⚠ **Why it matters more than a reset default sounds.** A session left in `auto` was left that way deliberately, usually because somebody is not watching it. Coming back as Manual means it stops at the first thing that needs approval and waits — which, from the phone, is indistinguishable from the stall that prompted the restart in the first place.

The runner already records the mode (`state.mode`, set when a `/mode` request is written). Resume should carry it over, or — if the CLI genuinely cannot be resumed into a mode — the console should say plainly that the mode was not preserved rather than reporting the default as fact.

Restoring it by hand works: `POST /api/sessions/{id}/mode {"mode":"auto"}` after the resume.

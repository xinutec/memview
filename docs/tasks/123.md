# #123 — Nix-build the console, but keep the plist pointing at a stable symlink

The fleet's rule is that a launchd agent runs a store path, never `~/Code/...`
(`reference_mac_agents_run_from_store`). The console is the exception that proves
why the rule needs a qualifier.

## The trap

Put a store path in `ProgramArguments` and every console change moves it, so the
plist changes, so home-manager's activation **reloads the agent** — unload/load,
which is SIGTERM. SIGTERM is the console's *stop* path: it takes every session
down on purpose. Pinning the plist would therefore make each upgrade cost every
open conversation, which is exactly what `Roster::handover` exists to prevent.

## The shape that works

- Build with nix; install the result behind a **stable symlink**
  (`~/.local/libexec/agent-console`). The plist never changes, so home-manager
  never reloads the agent.
- `handover()` must exec that symlink, not `std::env::current_exe()` — Rust
  canonicalises, which would resolve back to the old immutable store path and make
  SIGUSR2 a silent no-op that looks like it worked. One-line change: prefer
  `CONSOLE_BINARY` when set.
- The **frontend is the risky half**, not the Rust. `build:console` is `ng build`
  plus rsync, and esbuild's macOS teardown abort can land before `index.html`
  flushes — thoth shipped a 0-byte index.html and crash-looped its agent 33 times.
  Never accept `test -d dist/…`; end the build in a bundle validation whose exit
  code is the check.

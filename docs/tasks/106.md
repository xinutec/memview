# #106 — The console's task reader points at a store we deliberately emptied

**The original symptom is fixed.** `/tasks` typed into the console produced no task list, and so did every other slash command — measured 2026-08-08: a command runs locally and answers as one complete `assistant` message with `"model": "<synthetic>"` and no `content_block_delta` before it, because nothing was generated. The live reader kept only tool calls from a completed message, on the sound rule that the deltas already carried the text, and that rule is wrong about the one case that has no deltas. One condition in `protocol.rs` (`SYNTHETIC`) and every command's output reaches the screen.

The two candidates that filing weighed are both settled: the CLI **does** execute slash commands over `--input-format stream-json` (candidate 1 refuted, `/context` came back with the whole context table), and the console did not need to originate anything.

## What is actually left, and it is not what was filed

`console/src/tasks.rs` reads `~/.claude/tasks/<session-id>/<n>.json` and `api.rs` serves it on two routes; the front page draws an `open/total` tally per session from it. **That store is the CLI's built-in task list, which this project has deliberately stopped using** — see `claude_tasks.py` and the `TASKS.md` + `docs/tasks/<id>.md` shape that replaced it, because the built-in list was re-sent as a `task_reminder` attachment 1.75 times per message and became 73% of a 3.7 GB transcript.

So the reader is aimed at a store that is emptied on purpose, and the tally beside each session will read `0/0` or go stale as sessions migrate. Two honest ways out:

1. **Repoint it at the repo.** Read the session's working directory for `TASKS.md` and count the open lines. Same shape on screen, a source that is now the truth, and it works for a session that has exited — the file is on disk either way.
2. **Drop it.** The tally, the two routes and `tasks.rs` together. The index is injected into every prompt already, so the agent has it; the question is only whether a person scanning the list wants the number.

⚠ **Decide before the tally silently becomes a lie.** A `0/0` where there are 24 open items is worse than no number at all — this console has spent a day fixing exactly that class of thing.
